## Goal
New subproject /Users/sahilpohare/Lifemap/cms with Payload CMS 3 (official create-payload-app setup, TypeScript), managed by the LifeMap team only.
- Database: @payloadcms/db-postgres, its own database/schema on the same Postgres (PGlite or a local Postgres for dev; check what Payload supports and prefer the official path).
- Media: @payloadcms/storage-s3 to a private, encrypted S3 bucket in eu-west-1 (local disk in dev).
- Editor: Lexical rich text (built in). Drafts, versions, scheduled publish, live preview where cheap.
- Staff-only admin with Payload's own auth; no public sign-up.
- Multi-tenant ready: official @payloadcms/plugin-multi-tenant installed, content global for now (one "LifeMap" tenant), so credit unions can get their own content later.
- Collections (start small, from what the app shows today): Videos (title, topic, presenter, Vimeo URL/ID, captions .vtt upload, transcript, duration, thumbnail from Vimeo oEmbed), Topics/Focus areas, Explore categories, Calculator intros and help copy, Ask answers, Articles, Personality descriptions, Legal pages (privacy notice etc., with version ids matching the consent versions).
- Seed script that imports the content currently hard-coded in app/src (*.data.ts copy, videos.data.ts, mortgages.data.ts, ask answers, personality data) so the app can switch without visual change.
- Read API for the app: Payload REST (published only, public read for published content, no drafts), CORS for the app origins.
- SST: deploy the CMS (Next.js via sst.aws.Nextjs or as Payload recommends on AWS), link the database, bucket and secrets; not deployed now.
- docs/cms.md: how to run, add a collection, publish, and how the app reads content.
Rules: ponytail; libraries only (Payload's official packages and plugins), no hand-rolled admin or APIs; do not over-test; financial rules and rates stay in app code, not the CMS.
