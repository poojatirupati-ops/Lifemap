# Sign-in, create-account and sign-out screens
status: done
deps: T27,T28,B2
files: src/screens/SignIn.tsx, src/components/auth/*.tsx

## Goal
Public route /sign-in (the wall after the reveal, sec 12 amended): create account (first name, email, mobile) or sign in; 6-digit email code; passkey / Face ID as an extra; consents UNTICKED ('Use my details to build my plan' required, 'Send me reminders and updates' optional); 'How LifeMap makes money' link. Returns to returnTo or /home. Mobile is collected but SMS verification is later (see COVERAGE). Sign-out button component used by Me. Calm error and resend states.

## Done when
Component test with fake client: consents start unticked and submit is blocked without the required one; code step; success navigates to returnTo; renders at 375px. npm run build and npm run lint pass.

## Review (changes)
Build, tsc, lint (only the fast-refresh warning shared with the other screens) and all 82 tests (17 files) pass now; the other cards' failures are gone. I also drove the real SignIn + Shell + authClient with a stubbed fetch in a scratch copy (deleted). Only B5 files are in play (screens/SignIn.tsx, components/auth/*). Issues:
1. returnTo is lost (Done-when "success navigates to returnTo" is not met). Repro: signed out, open #/plan, get sent to #/sign-in?returnTo=/plan, sign in with a code. Final hash is #/home, not #/plan. Cause: authClient.signIn sets the session, Shell's guard (route.ts resolve) already does location.replace('#/plan'), then goBack in SignIn.tsx reads location.hash.split('?')[1], which is now empty, and sets #/home. Fix: the guard already handles returnTo and the open-redirect check, so make onDone a no-op (or drop goBack, safe() and the unused import of the hash parsing from SignIn.tsx). The test never saw this because every test mocks onDone. Add a test that renders Shell + SignIn with a fake client/session and asserts the hash is returnTo after the code step.
2. Sign-in mode creates accounts without consent. api/src/auth.ts has no disableSignUp, so a new email entered under "I already have an account" gets an account on the first verified code, with no required "Use my details to build my plan" ticked and no consent record. Either show the required consent whenever the email has no account (or in both modes), or require the consent at the code step; add a test for it.
3. The passkey button can never work. Nothing in the app registers a passkey (no passkey/generate-register-options call anywhere in src), so authenticate always fails; spec P1 says passkey is "offered as an extra after verification", i.e. an enrol step after the code. Also a failed or cancelled passkey shows nothing (useSignIn.passkey only calls onDone on success), against "calm error states". Fix: add the enrol offer after sign-in (or remove the button until a card covers it and say so in COVERAGE), and show a calm message on failure.
4. Dead link: "How LifeMap makes money" goes to #/how-we-make-money, no card builds that route, and the guard treats it as a protected unknown route, so signed out it redirects to /sign-in?returnTo=/how-we-make-money (the link looks like it does nothing and poisons returnTo). Use a public route that exists (or add a public sheet/inline disclosure in components/auth, a few lines of copy in signIn.data.ts) so the link shows something.
5. Consent and personal data handling: onSignup writes name, mobile and consents to localStorage on submit of step 1, before the email is verified and before any account exists; nothing clears it on sign-out, so on a shared phone the next person's flow leaves it behind, and the consent timestamp is recorded for people who never verify. Nothing reads 'lifemap.signup' yet (grep: only SignIn.tsx), so as shipped name and mobile are collected and then thrown away. At minimum write it after successful verification, clear it in the sign-out path, and name the consumer card (B12 or T28) in the card file so the supply is owned.
6. Small: `safe()` in SignIn.tsx duplicates the one in shell/route.ts (goes away with item 1); inline style on the fieldset in ConsentChecks.tsx belongs in auth.css and the fieldset has no legend; DetailsStep key={String(create)} wipes typed email when toggling modes (keep email); pasting "123 456" into the code box loses the last digit because maxLength=6 truncates before non-digits are stripped (strip first, then slice); the 375px claim is untested (CSS looks right: single column, 16px gutter, 44px controls), which is acceptable but say so.
