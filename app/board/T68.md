status: done
deps: T26

## Goal
Content for the floating Ask button: a bottom sheet with short plain-English answers and a glossary of the money terms used in the app (sec 10.2: help and explanations only, never advice). Static data; the AI chat is out of scope. Footer: 'Guidance, not advice.' The button itself is owned by T27.

## Done when
Component test: opens, lists answers, closes with Escape, focus returns. npm run build and npm run lint pass.

## Review
- DEFECT: focus does not return to the opener in a real browser. Sheet's dialog ref calls showModal() during commit, which moves focus to the Close button; AskSheet's useEffect then reads document.activeElement (now Close, inside the dialog) as the "opener". On close the dialog unmounts and focus lands on BODY. Verified in Chrome with a real harness: opener focused, click, activeElement was BUTTON "Close", after cancel activeElement was BODY. Fix: capture the opener before the dialog mounts (for example in render, or a useLayoutEffect declared before Sheet mounts, or capture in a ref during the open transition when open flips false to true before children mount), and restore it in cleanup.
- TEST CANNOT FAIL FOR ITS REASON: src/test/AskSheet.test.tsx mocks showModal as a plain setAttribute, so focus never moves into the dialog and the test passes while the real behaviour is broken. Make the mock move focus into the dialog (focus the first button) like the real showModal, then assert focus returns to the opener.
- Minor: the test fires a synthetic cancel event, not an Escape key; fine, but say so in the test name or keep as is.
