# Multi-tenancy with Better Auth organizations (backend)
status: done
deps: -
files: ../api/**, ../docs/tenancy.md

## Goal
Tenants are Better Auth organizations (organization plugin). User types:
- Platform admin (LifeMap staff): Better Auth admin plugin role, no customer data by default.
- Independent users (HNWIs etc.): members of a built-in "LifeMap Direct" organization, joined automatically on first sign-in when no tenant applies.
- Tenant users (credit unions / white-label / channel partners): organization roles "admin" (tenant staff) and "customer" (tenant end users), via the plugin's access control (createAccessControl) with only the permissions needed now.
- Advisers come later (vendors): leave room (an adviser firm is just another organization type), do not build.
Tenant resolution: by request hostname (tenant domain/subdomain -> organization), falling back to LifeMap Direct; the active organization lives in the Better Auth session (activeOrganizationId). A user signing in on a tenant's domain joins that tenant as customer.
Data isolation: every tenant-owned row (plan, consent_event, notice_ack, export/delete scope) carries organization_id; queries always filter by the session's active organization and user; add Postgres row-level security policies as a second wall where Drizzle allows it (document if deferred). Tenant config per organization: branding tokens (name, logo URL, colours), feature flags, partner rate overrides; GET /api/tenant returns the public config for the current host (no auth), admins update it.
GDPR: export and delete scoped to the user within the tenant; a tenant admin cannot read customers' plans unless a permission and consent say so (not now).
Write docs/tenancy.md (one page): model, roles and permissions table, isolation, host resolution, white-label config, GDPR controller/processor note for the lawyer.
SSO (user: needed now): use Better Auth's SSO plugin (@better-auth/sso) so each tenant can register its own identity provider (OIDC such as Microsoft Entra ID, Google Workspace, Okta; SAML where the plugin supports it). Tie each provider to its organization, use domain verification so staff emails on the tenant's domain sign in through it, and auto-provision new SSO users into that organization with a role from the provider mapping (default customer, admin only by explicit mapping). Email OTP and passkeys stay for everyone else. Add Google and Apple social sign-in for independent users only if it is one config line each; otherwise list it as next.
Ponytail: use the plugin's tables, hooks and access control; no hand-rolled tenancy layer.

## User decisions (override the above)
- No custom models for tenancy: only Better Auth's organization, member, invitation (team), admin and SSO models. Tenant config (branding, host, partner rates) lives in organization.metadata, validated with zod; typed fields only via Better Auth additionalFields.
- Feature flags: per-tenant flags in organization.metadata.features with code defaults; GET /api/tenant exposes them; only that tenant's admins and platform admins change them; isEnabled(org, flag) helper; tests for defaults, override, cross-tenant denial.
