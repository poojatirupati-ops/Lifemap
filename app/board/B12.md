# Plan sync and carry-over of pre-login answers
status: done
deps: B3,T28,T19
files: src/state/sync.ts, src/state/carryOver.ts, src/state/sync.test.ts

## Goal
After sign-up/sign-in: if the server has no plan, PUT the local Discover answers/reason/personality (carry-over, never re-asked); if it has one, GET it and keep newer. Then PUT on change (debounced), 409 resolved by refetch, offline = no-op (local store stays source of truth), expired session pauses sync. Sign-out clears the local plan.

## Done when
Test with a fake fetch: carry-over on first login, debounce, 409 retry, offline no-op, sign-out wipes local storage. npm run build and npm run lint pass.

## Review (round 1, score 3)
Build, lint (only old warnings) and the 3 state test files pass; only the 3 card files touched; carryOver.ts is pure. Defects to fix:
1. Data loss: if the first GET in start1 fails (offline or 5xx at sign-in), wasIn stays true and reconcile never runs. The next edit PUTs version 0, gets 409, refetches the version and overwrites the server plan with local (verified with a scratch test: calls GET, PUT v0, GET, PUT v5, server plan replaced by the local near-empty one). Do not push until reconcile has succeeded; retry reconcile (reset wasIn on failure, or run it before any push). Add a test: GET fails once, then an edit, server plan survives.
2. Cross-account leak: SYNC_KEY meta and the local plan are not tied to a user. After expiry (or a cookie lapse seen at load, where had is false so nothing is wiped) a different person signing in on the same device gets the previous person's local plan PUT into their account, or their dirty flag pushing it over their server plan. Store the user id (auth.getState().user.id) in meta and wipe/ignore local when it differs from the signed-in user. Add a test.
3. Carry-over overwrites a real server plan: "dirty" is set by any local edit, including pre-login Discover answers on a new device or a shell effect that fires changed() on mount. With a server plan present and this device never synced for this account (meta.version 0 or no user baseline), reconcile returns push and the full server plan is replaced by 6 answers. The test "kept when local is newer" codifies it. Newer must not be decided by a bare dirty flag: when the device has no sync baseline for this user, adopt the server plan (or merge only the empty Discover fields into it). Update carryOver.ts and its test.
4. Local fromPublic is never cleared after carry-over or adopt (only the PUT copy is false), so the local plan still says it is not carried to the account. Clear it with setPlan under the applying guard.
5. Missing tests: 3-try cap on repeated 409; expired then signed-in resumes (reconcile runs again); carryOver.ts has no direct test of the adopt branch beyond sync tests (fine if covered by 3).
Minor: sign-out while dirty drops unsynced edits silently (acceptable per card, note in the summary); `let applying` is declared after its first use in start1 (works, move it up); start1 is a poor name.

## Review (round 2, score 3)
Build, 97 tests pass, lint only old warnings. Round-1 items 1, 2 (when uid is recorded), 3, 4 and the missing tests are fixed and the tests can fail for their reasons. carryOver.ts is pure. Remaining defects:
1. Sign-out during an in-flight reconcile restores the old plan (verified with a scratch test: GET gated open, set signed-out, release GET, local plan is again the server plan of the signed-out user and SYNC_KEY is rewritten with that uid, `ready` becomes true). onSession's signed-out branch runs clearLocal outside the `busy` queue, so reconcileNow / push finish after the wipe and write `quietly(plan)`, `save()` and `ready = true`. The next account then skips reconcile (ready already true) or sees the previous user's plan. Fix: after every await in reconcileNow and push re-check `live()` and the same uid (or a generation counter bumped by clearLocal / expiry) before writing local state or setting ready; add a test with a gated GET.
2. `applying` cannot work with the wiring this file prescribes (a useEffect on usePlan() calling changed()): the effect runs after quietly() has returned, so an adopt, a fromPublic clear or the clearLocal default plan all mark the plan dirty and cause an extra PUT (and re-create SYNC_KEY after sign-out). The "adopt never PUTs" claim holds only in the fake-setPlan test. Make changed() ignore a plan it applied itself (remember `applied = getPlan()` after quietly and return when getPlan() === applied) and test it with a setPlan followed by a deferred changed().
3. Dirty plus baseline keeps local even when the server moved on (GET version above meta.version = another device saved meanwhile): the offline device overwrites the other device's newer plan with no signal. The card says keep newer; at minimum when server.version > meta.version and local is dirty, do not silently push (adopt, or merge), or state the last-write-wins decision in the card and a test.
4. Minor: uid is only stored after a successful reconcile, so edits made while signed in but before the first successful GET carry no uid (page reload then another account signing in pushes them). Save uid in changed() when live.
5. Minor: a pre-login Discover carry-over is wiped when the device still holds another account's meta (cookie lapse then new sign-up); the test codifies it. Acceptable only if stated.
