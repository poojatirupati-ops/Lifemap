## Goal
Documents are read by the user's external provider through its own API. LifeMap owns the seam: one reader interface, an HTTP adapter for the provider, an example adapter for dev and tests, a read endpoint, and the app's confirm screens showing what was read.

## Built
- `DocumentReader.read({ documentId, kind, contentType, url, organizationId }) -> ReadResult { status, fields: [{ key, value, confidence 0..1 }], provider, raw? }` with a zod schema (`readResult`).
- `httpReader`: POST `{DOC_READER_URL}/read` with `Authorization: Bearer {DOC_READER_API_KEY}`, 12 s timeout (`AbortSignal.timeout`), reply zod-validated, provider names mapped to LifeMap keys by `PROVIDER_KEYS` (one table, per kind). `exampleReader`: today's example figures per kind.
- `DOC_READER=http|example`: example by default outside production; production uses http only with URL and key set, otherwise every read fails (fails closed). `lambda.ts` sets `DOC_READER=http` and bridges the secrets `DocReaderUrl` / `DocReaderApiKey` (added to sst.config.ts, linked to Api).
- `POST /api/documents/:id/read { kind }`: caller's document in the session's tenant, `documentUpload` flag. A reader error (timeout, bad reply, not configured) is stored as `failed`, logged without values. Stores `readStatus`, `readFields`, `readProvider`, `readAt` (migration 0007). `GET /api/documents/:id` returns them.
- Provider contract (request and reply JSON, names per kind) in api/README.md "Document reading".
- App: real uploads (flag on) now upload, then read through the endpoint in the same TanStack mutation (`useDocumentUpload(kind)`); the finance and Explore confirm screens show the reader's figures with their confidence (only the fields it found); a failed or empty read shows the existing failure path. "Example figures" shows only for provider `example` or a sample document. Sample documents (flag off, "Use a sample document", list items) keep the local sample figures and short scan.
