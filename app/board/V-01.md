# Automatic upload of CMS videos to Vimeo
status: done (direct uploads; media reads move to CloudFront)
deps: C-01 (CMS), CMS S3 media storage, jobs cron (CmsJobs)
files: cms/src/vimeo.ts, cms/src/vimeo-sdk.d.ts, cms/src/vimeo.test.ts, cms/src/components/VimeoUpload.tsx, cms/src/app/(payload)/admin/importMap.js, cms/src/collections/content.ts (Videos), cms/src/collections/Media.ts, cms/src/payload.config.ts, cms/src/payload-types.ts, cms/package.json, cms/.env.example, sst.config.ts (CMS section), docs/cms.md

## Goal
- Hard rule: file bytes never go through Lambda or the CMS server. Uploads happen only over signed URLs or directly to Vimeo.
- Videos: the editor's browser uploads straight to Vimeo with tus; the CMS only creates the upload ticket (`POST /me/videos`, `upload.approach: 'tus'`, file size).
- Vimeo privacy: hidden on vimeo.com, embeddable only on the app's domains (hostnames from `CMS_CORS_ORIGINS`).
- `vimeoId` and a Vimeo status (Uploading, Transcoding, Ready, Failed) on the video; the `vimeoPoll` job fills duration and thumbnail.
- Replaced Vimeo videos are deleted once no published version uses them; deleting a video record deletes its Vimeo videos.
- Media (images, .vtt captions): browser uploads to S3 with presigned PUT URLs (`@payloadcms/storage-s3` `clientUploads`). No video files in Media. Public read stays.

## Built
- `VimeoUpload` admin field (Payload `ui` field, `tus-js-client`): sends name and size to `POST /api/videos/vimeo-upload`, uploads the file to the returned `upload_link` with progress, then sets `vimeoId`, status Transcoding and clears URL, thumbnail and duration in the form; the editor saves.
- `vimeoUploadEndpoint` (staff only, 503 without `VIMEO_ACCESS_TOKEN`, validates `{ name, size }`) → `createVimeoUpload`: tus ticket, privacy `{ view: 'disable', embed: 'whitelist' }`, `PUT /videos/{id}/privacy/domains/{host}` per app origin.
- Removed: S3 pull upload, the Videos `file` field, the `not_configured` status, `video/*` in Media, `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` from cms deps.
- `deleteReplacedVimeo` (afterChange, on publish only): walks versions back to the previous publish and deletes our uploads the new published version no longer uses (draft-only uploads too). Each is deleted once, by the publish that dropped it.
- `collectVimeoUploads` (beforeDelete) + `deleteFromVimeo` (afterDelete): deletes every Vimeo video uploaded for the record across its versions. Pasted Vimeo URLs never: saving a URL clears `vimeoStatus`, and only versions with a status and no URL count as ours.
- `queueVimeoPoll` / `vimeoPoll` kept (polls from Uploading or Transcoding).
- Media: `upload: true` plus a beforeValidate check on the declared MIME type (images, `text/vtt`). A `mimeTypes` allow-list was not used: with it Payload downloads every client upload back from S3 to sniff the type.
- `payload.config.ts`: `clientUploads: true` on s3Storage. `sst.config.ts` (CMS section): `CmsMedia` with `cors: false` (drops SST's allow-all default) and `CmsMediaCors` allowing PUT from `cms.url` only.
- One test (`npm test`, Vimeo SDK mocked): tus ticket with the size, privacy, domain whitelist, returned upload link; status mapping.

## Open questions
- Payload still reads up to the first 1 MB of each image from S3 (header probe for width/height) after a client upload; .vtt files are not read. Payload has no switch to skip it. Acceptable, or store images without dimensions some other way?
- Public reads (`/api/media/file/...`, and admin thumbnails) are streamed from S3 through the CMS Lambda. storage-s3 `signedDownloads` would 302 to a presigned S3 GET instead, but the app's CSP (`img-src`, `media-src`, outside the CMS section) and a GET CORS rule for captions would need the bucket host. Turn it on?
- A ticket whose upload is abandoned, or an upload the editor never saves, leaves an unlisted Vimeo video. Clean these up (for example a job listing our account's videos not referenced by any version)?
- A media file refused by the type check is already in S3 (the browser PUTs before the record is created); it stays there unreferenced.
- Restoring an old version whose Vimeo video was replaced and published over shows a deleted video.
