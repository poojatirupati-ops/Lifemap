# API docs (OpenAPI, generated from the code)
status: done
deps: -
files: ../api/src/** (route definitions), ../api/package.json, ../api/README.md

## Goal
Generate the API docs from the code, never hand-written: OpenAPI 3.1 from the routes' zod schemas using Hono's official @hono/zod-openapi (or hono-openapi if migrating the existing @hono/zod-validator routes is much smaller), Better Auth's openAPI plugin for the /api/auth/* endpoints, and an interactive reference with @scalar/hono-api-reference. Serve GET /api/openapi.json and GET /api/docs; in production only for platform admins (the docs list tenant and admin routes). Every route documents request, response and error codes (401, 403, 404, 409, 413), the session requirement and the feature flag that gates it. README links to the docs and says how to export the spec file for the app team.

## Done when
/api/docs renders in dev with all routes (plan, versions, consents, me, export, delete, documents, bookings, tenant, admin, auth); one test checks the spec lists every mounted route; existing tests pass; no hand-written spec file.
