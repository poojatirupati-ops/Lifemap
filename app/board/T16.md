## Review (round 1, score 3)
Build, lint and 47 tests are green; data matches spec 12, 13, 16, 17 word for word; scoring is a faithful port except the points below.
1. Provisional flag is wrong. `full` = u10 and u11 answered, so a profile is shown as final with u9, u12, u14 unanswered. Verified: `riskProfile({q8:3,q9:3,q7:0,u10:3,u11:2,u9:3},{chips:['Shares or funds']})` returns Growth, provisional:false, with income stability and emergency fund never asked. The prototype only goes final when all 13 are answered (`umCount() === 13`). Make `full` require every id of the money-profile set (q6, u9, u10, u12, u14, u4, u11) and add a test for the half-answered case.
2. `personality` throws on an out-of-range option index (`personality({q2:9,q4:1,q7:0,q8:0})` gives TypeError). Answers come from the T4 store and later from the API (B12), so a stale or tampered value crashes Home. Ignore indexes that are not a valid option (one guard in a shared helper used by personality, riskProfile and myTerms); `riskProfile({q8:2,q9:2,u9:9})` also returns a null level with a non-null `want` and a mismatch line. Add a test.
3. `comfort` is null when Q8 is answered but Q9 is not (`riskProfile({q8:2}).comfort` is null). Prototype sets it from Q8 alone (D10 tile); set it before the early return.
4. Prototype's `keNote` (and KE_NOTE text, "Investing is new to you, so this stays at Balanced for now...") is dropped, yet `limit` can be 'experience'. Port it (flag or string) or the reveal and Me cannot explain the cap.
5. Dead field: `Question.help` in discover.data.ts is never used by any data (u10 uses `sub`). Remove it.
6. Tests: only 4 answer sets; none cover K13, K15, K16, K17, K14l/K14t, the horizon fallback argument, the self-rated-expert cap, or personality tie-breaks, so those branches can break unnoticed. Add a small table-driven test for the mismatch keys and the two caps.
7. Note for T35/T4 (not a defect here): answer ids are lowercase q2... and u-ids; the store must use them.

## Review (round 2, score 3)
Build, lint and 70 tests green. Round 1 points 1 to 5 are fixed and verified in code (full requires all 7 money ids, clean() guards personality/riskProfile/myTerms, comfort from Q8 alone, keNote and KE_NOTE ported, help removed). Domain is pure, files under 150 lines. Two defects remain.
1. The personality tie-break tests do not test ties. `personality({q2:0,q4:2,q7:1,q8:1})` scores A 2.5 vs B 1, and `{q2:1,q4:1,q7:1,q8:1}` scores B 2.5 vs A 1.5: both have a single top type, so the q2 rule, the q4 rule and the B,A,C,E order are never exercised (the test comment even says "tied"). If the `from('q2')`/`from('q4')`/ORDER logic broke, this test would still pass. Add real ties: one where q2 decides, one where q2 is not in the tied set and q4 decides alone, one where neither decides and ORDER picks (assert the exact key for each).
2. `keNote` is true whenever the experience cap is the binding one, including when the cap is 4 (u11 = 1 "Basics", or u11 >= 2 capped by chips). The test at line 103 locks this in: `riskProfile(FULL,{chips:['None']})` gives level 4 (Balanced-growth) with keNote true, so Me/reveal would tell someone who said they have invested in funds "Investing is new to you, so this stays at Balanced for now". Wrong copy for any ke > 3. The prototype has the same flaw, but the card asks the reveal to explain the cap, so fix it here: set keNote only when ke === 3 (a beginner) or have the chips-cap case return a different note. Add a test for u11 = 1 and for the chips cap asserting what is returned.
Minor, no action required unless the writer agrees: K14c text adds "Build 3 to 6 months of essential spending first." which is not in the spec or in the prototype's base MIS line (the prototype builds it dynamically from the cushion figures); keep, but note it for T35 so the figure-based version can replace it.
