# Email sender for sign-in codes (AWS SES)
status: review (backend: OTP, invitation and booking emails); app: invitation link handled in O-01
deps: M-01
files: ../api/src/auth.ts (sender only), ../sst.config.ts

## Goal
Production sends the OTP email through AWS SES (SESv2 SendEmail via @aws-sdk/client-sesv2), eu-west-1, from a verified sender set as an SST secret/config; per-tenant sender name from organization metadata branding. Dev keeps the masked log sender. No secrets in code.

## Done when
Unit test with the SES client mocked (correct to/from/subject, no code in logs); sst config has the SES identity and IAM permission; not deployed.

## Backend (review)
`sesOtp` in api/src/auth.ts (SESv2 SendEmail, plain text, no tracking, From name = tenant's organization name, RFC 2047 encoded); picked in api/src/app.ts only when `OTP_SENDER=ses` (set by lambda.ts with `OTP_FROM` from the linked `Email`), else production fails closed. sst.config.ts: `sst.aws.Email("Email")` from `LIFEMAP_EMAIL_SENDER` at deploy, linked to Api (ses:SendEmail). Test: SES client mocked with aws-sdk-client-mock (to, from, subject, no code or address in logs). Not deployed; SES sandbox exit and DKIM records are ops steps.
