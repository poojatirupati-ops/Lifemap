## Review (round 1, score 3)
Build, 82 tests and lint pass; cover and chips render correctly at 390 wide; nothing is fetched. Fix before merge:
1. Copy lives in the component: CoverLinks.tsx hardcodes 'I have an invite', 'Why we ask', 'Enter your invite code', 'From your adviser or employer.', 'Code', placeholder, 'Continue'. Move all of it to welcome.data.ts (user rule: copy in .data.ts).
2. CoverLinks.tsx bundles the link row plus two sheets (the invite form is a component of its own). Split into InviteSheet.tsx and WhyAskSheet.tsx (CoverLinks stays the thin link row).
3. 'Something else' note has maxLength 120; the prototype D1 and spec say max 60 (this text is later carried into the account). Set 60. The invite code input has no maxLength; it goes unbounded into plan.entry. Add a sensible limit (about 20).
4. Cover photo is served from public/ and is not in the service worker precache (dist/sw.js lists no cover-photo.jpg), so the installed PWA shows no photo offline; spec 23 says embed it. Either import it as an asset from src (so Vite hashes and precaches it) or embed it, and keep it out of public/.
5. Invite 'Continue' closes the sheet with no feedback (prototype shows 'Invite linked'). Show a short confirmation (a line in the sheet before closing, or on the cover) so the customer knows the code was taken.
6. Continue and Skip on WhyHere do the same thing with nothing selected. Prototype disables Continue until a chip is chosen; do that so Skip is the only no-answer path (the card says chips are optional, which Skip satisfies).
7. Stale data: deselecting 'Something else' leaves whyNote in the store. Clear it when 'other' is removed.
8. Tests: nothing checks that Let's start, Continue and Skip navigate to the next screen (/why, /discover), and the store is shared across tests without a reset. Add navigation assertions and reset the store between tests.
9. Use min-height:100dvh (with 100vh fallback) on .cover; plain 100vh pushes the links under the browser bar on phones.
