## Goal
Better Auth mounted on the Hono app at /api/auth/*: email OTP or magic link, passkey plugin, Drizzle + Postgres adapter. Dev email sender logs the code; sender is one function to swap for SES. Secrets from env, never committed. Consents (unticked by default) stored with timestamp. Phone/SMS OTP is a later card.

## Review (changes)
Build and tests pass. Issues:
1. POST /api/consents stores any body key as `kind` (unbounded, attacker-chosen strings) and a malformed JSON body throws a 500. Allowlist the kinds (terms, marketing) and treat bad JSON as 400.
2. createAuth defaults sendOtp to logOtp, so a prod wiring that forgets the sender logs live OTP codes to CloudWatch. Make the sender required, or default to logging only when NODE_ENV !== "production".
3. Goal says Better Auth is mounted on the Hono app, but src/app.ts is not wired and no card owns it (B3/B4/R1 do not list it). Add ../api/src/app.ts to this card's files and add the mountAuth(app, createAuth(connect()), connect()) call, with BETTER_AUTH_SECRET/DATABASE_URL read from env (sst.config.ts links Resource.*, so the env mapping needs a note or a bridge in lambda.ts).
4. Minor: connect() has no max:1 pool although the README says to keep one connection per Lambda; Better Auth's default rate limiter is in-memory, so per-instance on Lambda (OTP attempts are capped by Better Auth's allowedAttempts, so this is a known limit, mark with a ponytail: comment); passkey path (rpID/origin) is untested.
