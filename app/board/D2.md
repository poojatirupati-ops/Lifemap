# Design system port: base styles and motion
status: done
deps: -
files: src/styles/base.css, src/styles/motion.css, src/styles/tokens.css (additions only), src/main.tsx (imports)

## Goal
Port the prototype's shared look into real CSS: base reset, typography (Inter), buttons, cards, chips, inputs, progress bars, toasts, from LifeGoals-Customer-Journey-Prototype.html. motion.css: the prototype's screen-enter (up/rise/pop/fadein), tab pop, button press, shimmer/sweep, float, orbit and gauge-fill keyframes as reusable classes using the prototype's --ease, plus one @media (prefers-reduced-motion: reduce) block that disables them. No JS animation libraries.

## Done when
build passes; a test asserts motion.css contains reduced-motion handling; side-by-side screenshots of buttons/cards/chips at 375px match the prototype; keyframe count is in the same ballpark as the prototype's used set.

## Review (round 1, score 3)
Build and 114 tests pass; computed styles of .btn/.btn.sm/.chip/.chip.sel/.card/.pill match the prototype at 375px. Fix before done:
1. Press feedback is dead on animated elements. The entrance classes (.m-rise, .m-up, .m-page, .m-stagger>*) use fill-mode `both`, so the final keyframe `transform:none` stays applied forever and beats `:active{transform:scale(.97)}` (verified in the browser: a pressed .btn inside .m-stagger and a .card.m-rise both stay at matrix(1,0,0,1,0,0)). Use `backwards` fill for entrance animations (the end state equals the natural state). Same trap will block hover lift.
2. Prototype hover lift is missing: `.btn/.chip` translateY(-1px) on hover, `.card` translateY(-2px) + --shadow-h, with the prototype's `transition: transform .3s var(--ease), box-shadow .3s var(--ease), ...`. Base .btn/.chip transitions are .12s only. Also `.chip.sel` pop (animation:pop .35s) on selection is not wired.
3. `[class*="m-"]` in the reduced-motion block matches any class containing "m-" (verified: `item-row` matches; later `form-`, `claim-`, `system-` will too). Use `[class^="m-"],[class*=" m-"]`.
4. `.bar i` fill uses var(--grad) (135deg #2A7F8C to #246B77); the prototype end state is `linear-gradient(90deg,#08D9B8,#0A7A85)`.
5. `.toast>*` shape differs: prototype end state is a pill (radius 999px, padding 12px 18px) with the `up .35s` entrance; here radius 16px and no entrance animation.
6. `.in` has no :focus style (prototype: border-color teal and a 3-4px teal ring). Minor: .btn.ghost bg/border and .btn.sm shadow differ slightly from the prototype.
7. The press rule includes bare `button`, which scales every button (including ones that later carry their own transform); limit to the prototype's list.
8. Writer's own gap: no side-by-side screenshots were taken. Nothing in the app consumes the new classes yet, so fidelity is only checkable via a swatch; keep that in mind for later cards.

## Review (round 2, score 3)
Verified in browser (375/768/1280 swatch, no horizontal scroll, .in focus ring OK, toast pill OK, .bar gradient OK, fill-mode `backwards` OK); motion.test.ts passes. Remaining defects:

Press feedback still dead on `.btn` with a mouse (and with sticky touch hover). `.btn:not([disabled]):hover` has specificity 0,3,0 and beats `:is(.card,.chip,.btn):active` (0,2,0), so hover+active keeps translateY(-1px) and never scales (verified by replaying the rules with .H/.A classes: `.btn|H A` = matrix(1,0,0,1,0,-1); .chip and .card correctly give scale .97). The prototype uses `*{animation:none!important;transition:none!important}`. Fix: use that universal block (simplest, correct) or add the missing selectors.
3. Tests cannot fail for the reasons they exist: the reduced-motion test only greps for the media-query string, the others grep source text. Add a real check for items 1 and 2 (e.g. assert the reduced block targets `*`, and that no `:hover` rule on .btn out-specifies the active rule).
Not D2 faults: `npm run build` currently fails in tsc on another card's file (src/engine/project.ts TS1005, mid-edit) and one other test file fails to transform; vite build and motion/ui tests pass.
