## Goal
Better Auth client for ../api: signUp/signIn with email code, passkey sign-in, signOut, getSession; useSession() returns {status: 'loading'|'signed-in'|'signed-out'|'expired', user}. Expired session: any API 401 flips status to 'expired' (one fetch wrapper `apiFetch`, used by every client card). Local-only mode is impossible once signed out for protected data.

## Done when
Test with a fake fetch: signed-out, signed-in, and a 401 from apiFetch sets 'expired'; signOut clears it. npm run build and npm run lint pass.

## Review (round 1, score 3)
Verified by running: `npx tsc -b`, `npm run build`, `npm run lint` and `npm test` (14/14) all pass; endpoints and bodies match the installed Better Auth passkey/emailOTP plugins (GET generate-authenticate-options, POST verify-authentication with `{response}`, send-verification-otp, sign-in/email-otp, get-session). No dependency added, no files besides the three identity files. Defects to fix:
1. Passkey path is untested and throws instead of failing soft. The user cancelling the browser prompt makes `navigator.credentials.get` reject (NotAllowedError), and a non-OK or non-JSON options response makes `.json()` throw, so `signInWithPasskey` rejects rather than returning false. It is a security-relevant, hand-rolled WebAuthn serialisation (b64u/unb64u, field mapping) with no check at all. Wrap in try/catch returning false, and add one test with a stubbed `navigator.credentials.get` and fake fetch asserting the verify body shape and a cancel returning false.
2. Inconsistent error contract: `getSession` swallows network errors, but `sendCode`, `signIn` and `signOut` (only the post) reject on offline. Make `sendCode`/`signIn` return false on a network error, so B5 does not need a try/catch it will forget.
3. Better Auth's get-session returns 200 with null for an expired session (not 401). `getSession` called while 'signed-in' with a null result sets 'signed-out', so a revalidation hides expiry. Make that case 'expired'; cover it in the test.
4. Test gaps: `sendCode` and the offline branch are not exercised. `useSession` is untested (one small renderHook test: loading then signed-in via the fake).
Note (not for this card): no Vite dev proxy and no CORS/trustedOrigins on the API, so the default `VITE_API_URL=''` hits the Vite server in dev. Needs an owner (B5/deploy card).

## Review (round 2, score 3)
Verified by running: `npx tsc -b`, `npm run build`, `npm run lint`, `npm test` (18/18) pass. Round 1 items 1, 2 and 4 are fixed and tested (cancel, bad options, offline sendCode/signIn, useSession); only identity files for this card. One real defect left:
1. `getSession` treats every non-OK response as "no session": `res.ok ? json : null` then null while 'signed-in' sets 'expired'. A 500/502/503 (Lambda cold start, deploy blip) on revalidation therefore signs the user out as 'expired', and the catch branch sets 'signed-out' (user wiped) when offline while signed-in. Only a 401 or a 200 with null means the session lapsed. Fix: on a non-OK non-401 response or a thrown error while 'signed-in', keep the current state (return without set); on 'loading' fall back to 'signed-out'. Add one test: signed-in, then a 503 and then a thrown fetch, status stays 'signed-in' with the user intact. (This matters for the offline PWA card T69, which needs the cached plan to stay reachable on a flaky network.)
Minor, optional in the same edit: the passkey test does not cover verify-authentication returning non-OK (one more `expect(...).toBe(false)`).
Note (not for this card): Vite dev proxy and CORS/trustedOrigins still need an owner (B5/deploy card).
